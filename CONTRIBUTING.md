# Contributing

Small, focused contributions are welcome.

1. Create a branch for the change.
2. Keep ACV limited to code analysis and reporting.
3. Add or update tests for behavior changes.
4. Run `python -m pytest` before opening a pull request.

Never commit API keys, private source code, generated reports, or `config.json`.

# PatchCourt contributions

Run the complete original ACV and new PatchCourt tests. Keep provider mocks explicitly labeled and preserve failed trials. New supported semantic fields need controls and abstention tests. Unknown fields must not silently disappear. Never accept model-generated Python into the reviewed fixture execution path. Historical cases need an upstream URL, immutable source, license, fixed assertions and honest environment scope. Keep API credentials out of commits and evidence.

Changes to source fixtures require independent review and deliberate hash updates. A model recommendation alone cannot promote a repair or knowledge record to verified. New live experiments must record every scheduled outcome, exact parameters and uncertainty.
